# Workbench API coverage

This page maps public API capabilities to the Playground and Dev Viewer controls.

## Workbench capability coverage

This is the API-to-Workbench audit for [issue #397](https://github.com/mors119/copc-adapter/issues/397), first reviewed on 2026-10-30 and refreshed for Adapter 0.8.0 on 2026-11-04. It is checked against the published declarations, both application hosts, the exact Playground package, shared schema/configuration/code generation, and regression evidence. The API option tables above remain the source for detailed public types and semantics; this matrix records whether each contract is discoverable and reproducible in each host.

### Exact package profiles and status terms

| Host | Exact package profile verified | Evidence |
| --- | --- | --- |
| Public Playground | npm 0.8.0 | apps/playground/package.json and package-lock.json; verified Registry integrity and checked the exact 0.8.0 tarball declarations. |
| Dev Viewer | workspace 0.8.0 | packages/adapter/package.json, apps/dev-viewer/package-lock.json, and apps/shared/schema/manifests.ts. |

The 0.7.0 workspace version quoted in issues #397 and #406 is stale for this checkout. The Playground now uses the exact published 0.8.0 package and the Dev Viewer uses workspace 0.8.0. Both hosts expose the custom elevation range and palette controls. The Playground retains a single-anchor Terrain workflow although Adapter 0.8.0 also has a batch Terrain API; its npm manifest continues to gate Dimension controls separately.

These are the exact package profiles verified in this audit, not claims about the earliest historical release of each field. Earlier introduction versions are not inferred from current declarations.

In the tables below, **P** means Public Playground and **D** means Dev Viewer. **Present** means a truthful control or workflow exists for the installed package and selected renderer. **Partial** means a UI exists but it covers only part of the public contract or needs a clearer capability/readback boundary. **Missing** means the exact workspace API exists but no Workbench control maps it. **Version-blocked** means the Playground's pinned npm declarations do not contain the API. When declarations do contain an API but the Playground manifest filters its control, the row calls out that manifest gate separately. **Host-only** means the setting needs caller-owned viewer, scene, resource, or callback state and is not a normal layer option.

Both apps use the shared schema panel with collapsible sections, and the Playground groups Source, Health, Data, and Code into tabs. Neither app labels its controls as Basic and Advanced yet. Recommended placement in the matrix uses **Basic** for common source/style choices, **Advanced** for memory, filtering, coordinate, streaming, and renderer-specific controls, and **Diagnostics** for measurements and readbacks. Keep complex editors behind disclosures. The Dev Viewer keeps its expanded diagnostics in its inspector; Playground exposes a smaller set of runtime and dataset diagnostics.

After a successful load, Copy code uses Playground's applied config or Dev Viewer's active config. Before a Playground load it shows the safe default example rather than unvalidated edits. Cesium style changes are reconciled through getStyle() after setStyle(); a rejected setter leaves the previous applied state and snippet active. Share links use normalized applied settings after load, omit source by default, and only include an explicitly selected safe URL; Files, Blobs, credentials, URL query/fragment values, callbacks, viewers, TerrainProvider objects, and grid bytes are not share state. Before the first successful load, Playground can share valid pending settings without claiming that a layer is active. These app snapshots are not a universal layer-options readback API.

The audit/contract lane owns this documentation snapshot. [Issue #406](https://github.com/mors119/copc-adapter/issues/406) defines file-level lanes and requires one integration owner/PR at a time for schema, config, host entrypoints, and codegen. The original NGA host integration merged in [PR #418](https://github.com/mors119/copc-adapter/pull/418). This change completes the outstanding OSGeo GTX profile and exact-grid checks; the temporary fixture stayed outside the repository. Remaining feature and research work stays with its existing issues, including [#314](https://github.com/mors119/copc-adapter/issues/314), [#404](https://github.com/mors119/copc-adapter/issues/404), and [#405](https://github.com/mors119/copc-adapter/issues/405).

The evidence abbreviations used below are: **S** = apps/shared/schema/test/schema.test.mjs; **C** = apps/shared/config/test/workbench-configuration.test.mjs; **G** = apps/shared/codegen/test/integrationCode.test.mjs. Those suites exercise registry metadata, plan/apply/share rules, and generated code generically; they are not a browser E2E for every individual row. Targeted browser evidence is listed where it exists. The #402 wrong-file checks need no external fixture. Exact OSGeo upload/cancel browser checks use `COPC_WORKBENCH_EGM2008_FILE`; the optional NGA raw Blob/ArrayBuffer smoke uses `COPC_NGA_EGM2008_FILE`. The local OSGeo fixture matched its pinned SHA-256 and was not added to the repository.

### Developer-only and unsupported seams

| Public option/seam | Classification and current handling |
| --- | --- |
| decoder — CopcPointDecoder; Cesium/Three/Core injection seam. | Developer-only. Not user-selectable, shareable, or reconstructible by generic Copy code. |
| renderer — CesiumPointRenderer or CopcThreePointRenderer injection. | Developer-only custom renderer seam. Normal user choice is the built-in Cesium renderer selector; Three uses its built-in renderer. Do not conflate injected renderers with ordinary appearance controls. |
| onPointPicked callback. | Developer-only application callback. The Workbench owns its own picker/popup and does not serialize callbacks. |
| debug boolean. | Developer diagnostic switch. Dev Viewer enables its debug adapter deliberately; no user-facing package option or share setting. |
| Generic loadGtxGeoidGrid() resources — public API for caller-documented GTX files. | Remains caller-owned setup outside both Workbenches because arbitrary CRS, units, epoch, interpolation, and license metadata cannot be verified from the bytes alone. The Workbench supports the separate fixed NGA EGM2008 profile; no File/path/hash resource is URL state. |
| custom CopcBackend object and RandomAccessByteSource. | Developer-owned integration resources. Built-in backend selector does not expose arbitrary objects. Generated examples need a caller-defined import/setup rather than pretending these are JSON settings. |
| streaming.refineDistanceMultiplier and Core maxPointsPerBatch — deprecated compatibility fields; refineDistanceMultiplier and maxPointsPerBatch no longer drive refinement/batching behavior. | Intentionally absent from Workbench and generated code. Use maxScreenSpaceError with optional hysteresis and maxConcurrentNodeLoads for active work. Existing deprecated declarations remain until their documented removal window. |
| Dataset-relative/Height Above Ground modes ([#404](https://github.com/mors119/copc-adapter/issues/404)), textured 3D Tiles color projection ([#405](https://github.com/mors119/copc-adapter/issues/405)). | Research only, not current public color modes. Do not register Workbench toggles. The latter is also distinct from imagery projection ([#328](https://github.com/mors119/copc-adapter/issues/328)). |

### Confirmed gaps and decisions

| Finding | Decision / focused tracker |
| --- | --- |
| Dimension styling/filtering is public in the npm 0.8.0 declarations and workspace, but the Playground manifest excludes it while the Dev Viewer exposes it. | The P/D mismatch remains against #398's both-host goal; the open [#113 Epic](https://github.com/mors119/copc-adapter/issues/113) still lists #398 as unchecked. Keep package and renderer gates; resolve the release-profile decision in that workstream before treating the feature as complete. |
| Arbitrary GTX and KNGeoid24 operations are not verified Workbench profiles. | Keep them out of the selector. The two fixed EGM2008 profiles are checksum-pinned, local-file-only, and nonserializable. Exact OSGeo Dev Viewer and Playground browser checks passed during this audit; the data was not committed. The OSGeo README identifies its profile as Public Domain, while NGA redistribution terms remain unverified. See [#402](https://github.com/mors119/copc-adapter/issues/402). |
| Terrain alignment has a public Cesium API and host commands in both Workbenches, with different package capabilities. | Preserve Estimate → Preview → explicit Apply. The Playground currently exposes single-anchor estimates; Dev Viewer also wires batch estimates. [#403](https://github.com/mors119/copc-adapter/issues/403) and [#399](https://github.com/mors119/copc-adapter/issues/399) own the UI and applied-state copy contract. |
| Generated code parity is verified for registered Workbench options and exact package profiles; feature-specific browser evidence remains separate. | Keep code tied to successful app state and reject unsupported/nonserializable settings. [#399](https://github.com/mors119/copc-adapter/issues/399) completed the registered-option matrix; #409 adds custom elevation to the shared mappings. |
| Attenuated point sizing can be selected when a non-shader Cesium renderer is active; the adapter then uses the fixed-size path. | [#314](https://github.com/mors119/copc-adapter/issues/314) owns renderer-specific Workbench availability and should cover this case. |
| Styling modes that need source fields may fall back to fixed cyan when the source does not provide that attribute. | The Advanced Attributes hint identifies requested style/filter and pick fields. Preserve fallback semantics; the adapter reports required-mode fields that were not requested separately from source-missing fields. |
| Shared option controls are accordion sections, not explicit Basic/Advanced tiers; Diagnostics are separate tabs/inspector sections. | Use progressive disclosure and preserve the [#314 shared shell](https://github.com/mors119/copc-adapter/issues/314); do not make every advanced field an always-open control. |

### Validation evidence and limits

The manifest tests verify the exact npm and workspace 0.8.0 profiles, defaults, and capability filtering. They confirm that the current Playground manifest excludes Dimension even though its installed declarations contain the API; the Playground shared-shell E2E asserts those controls are absent, while Dev Viewer has numeric-ramp and filter E2Es. The #400 regression coverage checks opacity and clipping; #401 checks required-field loading and A/E cache behavior; #399 checks applied-state code generation against exact consumers. For #402, this audit ran `apps/dev-viewer/e2e/vertical-grid.spec.ts` (4 passed, 1 skipped: the optional NGA raw Blob/ArrayBuffer smoke requires the NGA file) and `apps/playground/e2e/vertical-grid-workbench.spec.ts` (2 passed) with a local OSGeo GTX matching the pinned SHA-256. The original PR #418 passed its CI, package, packed-consumer, browser-shard, and Pages-build checks; its exact-grid cases had been skipped. The local fixture was not added to the repository. The OSGeo README identifies its profile as Public Domain; NGA redistribution terms remain unverified.
